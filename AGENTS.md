# AGENTS.md — Todos Island

Standing instructions for AI agents working in this repo. Read this first, every session.

## What this is

**Todos Island** is a Windows tray app (Electron) that reads two plain-markdown todo notes and reminds you via a Dynamic-Island-style pill that drops from the top of the screen. The notes are the single source of truth — the app is a lens over them, never a database.

## Why this app exists — the product core (read before designing ANY feature)

Confirmed with the owner (interview, 2026-09-26; persona sharpened 2026-09-28). This is what makes it different from every other todo app; a feature that fights these is wrong even if it is "standard" elsewhere.

**Who it's for (the persona every decision serves):**
- **Details swallow the main task.** The user doesn't forget because the task left their head. They dive deep into details, get pulled sideways, and lose the thread back to the few things that actually matter today. The app's job is to **pull them back to the main targets**, calmly and on schedule.
- **Constant background pressure.** They always feel that too much is happening at once. A long list makes that worse; a short, clear "now + next few" makes it lighter.
- **A picture memory.** They read shapes faster than words, so meaning lives in glyphs: `★` Now, `!`/`!!`/`!!!` priority, a short date like `28 Sep`, and `[ ]`/`[x]`. Prefer a mark over a label, and a label over a sentence.
- **Boring places get ignored.** If the list lives somewhere dull, they stop looking at it. The island has to be beautiful enough to catch the eye, and the look has to be changeable (themes, accent, light/dark, glass) so it stays fresh.
- **A simple, fixed routine.** Few tasks, a Now to work on, subtasks to break one down, tick them off, and report the day to a manager. Each of these must be **one easy action**: stage Now, tick, undo, share.

| # | Core why | What it means for code/design |
|---|---|---|
| 1 | **Push, not pull.** Tasks come to you. Built first for people who lose track of a task the moment the list is out of sight (focus / ADHD-style minds). A normal todo app waits to be opened, and opening a big window is itself a distraction. | Auto reminders are **ON by default**. The island is the main surface; the tasks window is secondary. The island shows itself, then tucks away. |
| 2 | **Few, not many.** People really work on ~1–3 things a day. Short-term focus lives here; long-term goals and projects live elsewhere (project boards and similar). | The default view is **Now (★) emphasized + a short top few**; the full list is one deliberate step away (expand / tasks window). This is a soft default: users may configure more, but defaults stay few. |
| 3 | **Notes are the state.** Plain markdown the user owns, editable anywhere. | The app never owns task data. More sources (MS To Do, Azure Boards, a DB…) may come later as a **one-time-setup connector**. Their behavior is undecided; don't design it without the owner. Markdown stays the default and the reference format. |
| 4 | **Time decides focus.** Work leads in work hours; personal leads after hours and on weekends. | The work/off-time schedule, dual cadence and `focusByTime` are **core**, not extras. |
| 5 | **The look is the motivation.** The Apple Dynamic-Island feel is what makes the user *want* to glance at it and review reminders; a dull place gets ignored, and a look that never changes goes stale. | Polish is a feature: Ink & Notation tokens, glass-look pill, light motion. Never ship a plain/utilitarian island. |

The user can hand-edit any note in any editor and still configure every attribute, with no UI needed and no syntax to learn beyond what people already type. | Every attribute must stay **typable by hand as a short, common token** in the line itself. It is bookkeeping, not an attribute the user sets, and a task without it is fully valid. The parser stays tolerant (any order, year inferred, legacy styles read). The composer accepts the same tokens as the note. A new attribute gets a new short token, designed with the owner. |
| 8 | **Glyphs over words, one action per step.** The persona remembers pictures, not text, and a daily routine only sticks when every step is instant. | State shows as marks (`★`, bangs, short dates, brackets), never as a word where a mark works. Staging Now, ticking a task or subtask, undo and share are each a single click or key. Don't add a confirm step, a menu hop or a label where a mark or a direct action already does the job. |

**Must never break (owner rule, 2026-09-26)** — every change keeps these:
1. A timed island pop **never steals focus** (keyboard/typing is never interrupted). Only the global shortcut focuses the island.
2. Every complete/delete (and every other note write) is **undoable**.
3. The app **shows exactly what it will write** before it writes when EDITING a task (the editor's "will write" line). **Owner exception (2026-09-27, v1.11):** the add-task composer has no preview line: what you type is the note line, and the priority/due chips mirror the parsed tokens. **Owner exception (2026-09-28, v1.13):** the side-panel editor SAVES ITSELF (no Save button). The "will write" line still shows the exact note line live, a no-op save writes nothing, and ONE Undo rolls back everything changed since the panel opened (see "Side panel"). **Owner exception (2026-09-30):** the visible "will write" row is GONE from the editor ("not needed"). `composeTask` still runs behind it (chips follow typed tokens, an empty title is refused): the title field turns red (`.invalid`) and the save flash says "a task needs a title".
4. **Honest failure:** a missing or unreadable note shows an error, never an empty "all done" list.
5. **The user's hands only:** the app writes notes only on the user's own clicks. AI agents never write through the app.

**Never becomes:**
- **A project manager:** no projects, boards, assignees or recurring-task engines.
- **A notes-keeping app:** no Notion-style knowledge base.
- **Heavy or slow:** no runtime deps, no framework; the tray app stays light and instant.

**Feature test:** before building anything, ask:
1. Does the default view stay few and focused?
2. Do reminders stay automatic?
3. Does the data stay in the user's source?
4. Does it stay light?
5. Can the user still set every attribute by hand-typing the note?

A "no" on any of these → propose it to the owner, don't build it.

**Defaults:** `DEFAULT_SETTINGS` in main.js are the owner's own tuned setup: 60/60 min cadence, 7 s dismiss (owner 2026-09-29; was 10), 5 s undo, 1 s hover, weekend-aware, autostart and sound on, hide from screen sharing on, shortcut `Control+`` (owner 2026-10-01; was `Control+Alt+T`; existing installs keep their saved one), share format Plain text (`shareFmt: 'text'`), Glass 38 % (`glassLevel: 3`), theme Mist + accent blue (owner 2026-10-01, back from Lagoon + teal), appearance System, label size S (`labelSize: 0`), task size M (`taskSize: 1`). Every new install starts from them. Change a default only on the owner's word.

## The note format (v3) — never break it

```markdown
- [ ] /now !! 24 Sep -- Task title
	description line (indented plain)
	- [ ] subtask (indented checkbox)
```

- Leading meta tokens, any order: `/now` active (working on it now, multiple allowed; any case) · `!`/`!!`/`!!!` priority · `D Mon` due (year auto-inferred; rolls to next year if >45 days past), then `--` and the title.
- **v3 (owner 2026-09-29):** the app WRITES `/now` and ` -- ` (fmtTask). Why: a bare leading `*` rendered as a bullet / indent in Markdown viewers, and the wide dash `—` can't be typed on a keyboard. The parser still READS v2 forever: `*` = Now, and `-`, `--` or `—` after the tokens. Unchanged lines stay byte-identical (old style stays until the app rewrites that line). Tests: parse.test "v3: …", "separators read", compose.test "typed /now".
- Three task states: open / active (`/now`, legacy `*`) / done (ticked; work notes move it under `## Done`)
- **Blank lines (owner 2026-10-01, bug fix):** with a Done heading, `addTask` and `uncomplete` (Restore) insert at `_endOfTasks()` = right after the last open task, never adding a blank line. Before, every add inserted an extra blank line before `## Done`, so empty lines piled up between the open tasks and the Done section. parse.test "never pile up blank lines". Blank lines already in a note stay until the user removes them.
- Subtask = indented `- [ ]` (tab or 2+ spaces; a single leading space is still top-level)
- **Subtask priority (owner 2026-09-29):** a subtask takes the same leading `!`/`!!`/`!!!` (`\t- [ ] !! -- Call Sam`). Importance ONLY: the app never gives a subtask Now or a due date (`subMeta` in parse.js reads just the bangs from typed text; add/rename honor them, `setSubtaskPriority` changes it; rename without bangs keeps the old priority). Snapshot `subs[].p`. The island lists open subtasks most important first (stable); the tasks window keeps note order; the Edit panel lists OPEN subtasks first, then done (owner 2026-09-30). Panel: ONE bang button per subtask (`.sbp`) steps none → ! → !! → !!! → none (session undo like every subtask write).
- Description = indented plain lines in the task's block
- **Inline formatting (owner 2026-09-29):** titles, notes and subtasks may hold plain Markdown marks — `**bold**`, `_italic_` (or `*italic*`), `~~strike~~`, `<u>underline</u>` (Markdown has no underline; Obsidian/GitHub render the tag). The snapshot keeps titles RAW (no more `**` stripping — a subtask's `t` is its address, and a stripped one broke ticking bold subtasks). Renderers show them via `UI.inline` (escapes first); aria labels use `UI.plain`. Typing them: `UI.fmtBar(field)` = a small solid pop-up (B · I · S · U, `.fmtbar` in tokens.css) over a selection in the composer, the panel title, the new-subtask field and a subtask rename field, plus Ctrl+B / Ctrl+I / Ctrl+U / Ctrl+Shift+X; a mark toggles off when applied again (`UI.toggleMark`, fires `input`). WhatsApp share converts them to its own marks (lib/share.js `waMarks`).
- **Hidden stamp (v1.10, owner 2026-09-27):** optional HTML comment at the END of a top task line: `<!-- c:2026-09-27T14:05 u:2026-09-27T15:10 -->` (c = created, u = last updated; local time, minutes). Markdown renderers hide it. `splitStamp` strips it before `parseMeta`, so titles stay clean. Only this exact `c:/u:` shape counts; any other trailing comment stays in the title. Hand-typed tasks don't need it.
  - **Who stamps:** `NoteFile._touch` sets `u` on every REAL change to a top task: title/priority/due/Now (`update` compares the formatted line before and after, so a no-op save stamps nothing), description change (`setNotes` compares), Now toggle, subtask add/tick/delete (the parent), complete (u = the done date), restore. `addTask` writes c and u. Reorder/move is position, not content: no stamp. Old tasks never get an invented c. The toggle undo restores the old u exactly (`prevU`); block undos restore the captured raw lines.
  - **Ordering (snapshot in main.js; island + tasks window use it; Share lists latest-updated first, owner 2026-09-29):** Now first → due date (soonest; none last) → priority → last edit (newest). Ties keep note order (stable sort), so drag-reorder now only decides among tasks that tie on all of these. **Done list:** newest done first by u; unstamped done tasks keep note order after them. Work notes also FILE each newly done task at the top of `## Done`, so the note reads in that order.
  - The editor's "will write" preview shows the task line without the hidden stamp (the stamp is added at write time).
- Parser also accepts legacy trailing styles (`— !! — due:2026-09-24`) and always WRITES v2.1
- **Invariant:** unchanged tasks emit their raw line verbatim → clean round-trip is byte-identical. Every parse.js change must keep `npm test` green (50 parser asserts, incl. stamps; the two real-note round-trip tests activate via `TODO_WORK_NOTE`/`TODO_PERSONAL_NOTE` env vars).

## Reminder scheduling (v1.3)

`lib/schedule.js` is a **pure** function `nextFireAt(settings, lastShown, now)` — no timers inside; main.js polls it every 15 s from the tray tick.

- **Dual cadence:** `workIntervalMin` inside the workday, `offIntervalMin` outside — each with its own on/off toggle (`workRemindersOn` / `offRemindersOn`). Both off = manual mode (never auto-fires).
- **Night guard:** nothing fires between midnight and `dayStart`; evening fires never cross midnight (they clamp to tomorrow's start — no 00:00 pops, honest tooltips).
- **`weekendAware`** means weekends run the OFF-hours schedule (personal time), NOT total silence. With it off, weekends count as workdays.
- **`weekendDays`** (v1.9): `auto` | `sat-sun` | `fri-sat` (Settings → Advanced → Weekend days). `auto` resolves in main from `app.getLocaleCountryCode()` (the `FRI_SAT` country set → Friday + Saturday, else Saturday + Sunday); schedule.js only ever sees the resolved value (`isWeekend`). The owner's weekend is Friday + Saturday but their Windows region is GB, so their install needs the explicit `fri-sat` pick.
- **`focusByTime`** (default on): the island shows work tasks only during work hours, personal only outside. The filter lives in island.js rendering ONLY — the snapshot always carries both sections, so the tasks/share windows are never filtered.
- Any cadence change must keep `lib/schedule.test.js` green and ideally add a case for the new behavior.

## First run & task mode (v1.4)

- **Task mode** `settings.mode`: `both` | `work` | `personal`. A disabled note is never read (no section, no error, no source), its tab and Settings rows hide, and the composer targets the enabled note. `focusByTime` filters the island only in `both` mode, because a one-note user would otherwise get an empty island half the day. Switching a note ON in Settings creates its file if missing (`createNote`, `wx`: never overwrites).
- **Settings reset (v1.6.1, owner's iron rule 2026-09-27):** the `reset-settings` IPC writes state.json ONLY — `state.settings = { ...DEFAULT_SETTINGS }`. It NEVER creates, deletes, or modifies a note file (deliberately no seeding either; missing default notes surface as the honest missing-note error, and repair covers the next launch). It is undoable like every action: undo kind `settings` restores the captured settings object through the same `applySettingsSideEffects(prev)` (shortcut/autostart/update/glass/lang side effects, NO file work). The `save-settings` handler must NOT be reused for reset — it rejects nonexistent default paths and seeds missing note files. Settings → App also has **Run setup again** (`open-onboarding` IPC = the tray's re-run; merge-over, never a wipe).
- **Onboarding** shows only when there is no state.json. A state.json without `onboarded` is an existing install, and `onboarded` is set to true. Until onboarded: no launch pop, no timed pops, and tray/shortcut/second-instance all open the setup window.
- Flow: Welcome → Your tasks (mode + "Use existing file…" / "Choose folder…") → Reminders (on, hours, every, Start with Windows) → Ready (the real island drops in).
- **The stage (v1.6):** a miniature desktop above the steps (`#stage`, an aria-hidden illustration). Its scene follows the step:
  1. a note line types itself and becomes a glass island;
  2. the note files, with their live pick status;
  3. a 24 h day ribbon of drop-ins, drawn from the same rule planSetup writes and updated live as the inputs change;
  4. the shortcut keycaps press themselves and the island answers.
  - Glass cards sit over a color field (`.sb` blobs). Transitions sit ON the glass elements, never on an ancestor (the backdrop-filter gotcha).
  - Fully i18n: `ob.*` keys, Arabic RTL; notation stays LTR.
- **Repair / re-run:**
  - An onboarded install whose EVERY enabled note is missing opens setup at the notes step, with a notice naming the missing notes. This happens on manual launches only; `--hidden` login boots stay quiet.
  - One missing note out of two stays the honest error.
  - Tray → "Set up again…" re-runs setup. In a re-run, Skip becomes Cancel and changes nothing.
- **Never ship a state.json.** v1.4.1's installer carried the developer's dev-era `app/state.json` (real note paths). The legacy next-to-main.js migration adopted it on fresh PCs: onboarding was skipped and the app opened on two "can't read" errors.
  - The migration now runs only unpackaged, and never in sandbox runs.
  - build.files excludes `state.json` and `*.log`, and verify-dist FAILS if either is in the asar.
  - Sandbox runs create default notes inside their own userData, never in the real Documents.
- **Skip** (button, Esc, or closing the window) = Personal only, one `personal.md` in `Documents/todos-island/`, defaults untouched. Picking nothing = the note is created in that default folder. A picked folder that already holds the note name → adopted, not created.
- `planSetup` (lib/setup.js) is the single rule for all of this; main.js only performs the plan.
- E2E: a fresh `TODO_ISLAND_USERDATA` dir (no state.json) triggers onboarding. `TODO_ISLAND_PICK=<path>` answers the native file/folder dialog in sandbox runs. `applyAutoStart` is a no-op in sandbox runs, so tests never touch the real login item.

## Undo (v2)

In-memory `undoLog` Map in main.js: one tokened entry per interaction, exact rollback material (`captureBlock` = task lines + index). One-shot per token; entries die via the popup's own `undo-expire` countdown — there is NO sweeper interval and nothing persists to disk. If you add an undoable action, follow the same shape (see `delete-task`).

## UI contract (v1.4 redesign)

- **Vocabulary:** the `*` state is **Now** (★); clearing it is **Not now**; children are **subtasks**. Undo verbs come from `UI.undoText` only.
- **Row layout (owner, 2026-09-27, after the promo film):** rows have **no checkbox**; the title leads and a right-hand `.meta` holds subtask badge · priority · date. The Now card keeps `[ ]` on the left and puts priority · date · ★ on the right. **No pencil in the meta any more** (2026-09-28): edit is the corner tab below.
- **Corner Edit tab (owner pick "D", 2026-09-28; demo `design-demos/row-edit.html`, private):** `UI.editTab(host, { onEdit, onLeave })` (ui-shared.js, style `.etab` in tokens.css) = ONE floating glass "✎ Edit" tab per list, placed by JS on the top-right edge of the row you **rested** on, in the list's host (`#wrap` in the island, `.list-sheet` in the tasks window) so it is never clipped by the row and never takes layout width. It appears only after the **`hoverSec` dwell** (the same rest that unfolds an island row; default 1 s): passing over rows to reach another shows nothing (owner: flicker is annoying). Island: rows AND the Now card; click = `editFromIsland`; the tabs arrive after `TAB_REST_MS` = 0.8 s (owner 2026-09-30; or hoverSec if shorter) — the unfold keeps `hoverSec`. Tasks window: open rows only, a **600 ms rest** (`REST_MS` in window.js; owner 2026-09-30, was 200 — the tabs, peek and full title came too eagerly; the island keeps `hoverSec` because there you mostly view); click = the editor. **Delete (and the ☆ Now tab) live beside Edit** in the tasks window only: `editTab(host, { onDelete })` adds a trash tab (`.etab-del`, danger hover); the island passes no `onDelete` and never deletes. The tasks window's today date shows just "today" (short form); the row's aria label keeps the full wording. `.meta` is as tall as the title's FIRST line, so marks center on it even when a title wraps. Bangs render at 0.82 × task-text size, weight 700 (owner 2026-09-30: full size took too much room — island + tasks window); no priority = nothing (no placeholder dot). **Clickable (owner 2026-10-01):** the mark (`[data-prio]`, island rows + Now card + tasks-window rows) steps ! → !! → !!! → none (`PRIO_NEXT`), never stages Now, and is undoable (a one-off `session` on `update-task`; the tasks window's 0–3 keys now use the same `setPriority`, so they are undoable too — they weren't). No priority = an EMPTY `.bang.ghost` that draws a faint "!" via `::before` only on the rested row (`.hovered` island / `.wrow.dwelt` window), so nothing shifts; its text stays empty (E2E reads `.wmeta .bang`). E2E `prio-click+undo` / `island-prio-click` → both `*-roundtrip: byte-identical`. The Now title has **no highlighter** (owner: ugly), and the M2 highlight swipe is gone. A row is completed with Space/x (keyboard), or by staging it and ticking the card's `[ ]`.
- **Island: few first, more on scroll (owner 2026-09-28, round 2 — the "N more" pill is GONE, no button):** every appearance lists `ISLAND_FEW` = 5 non-Now tasks (across the shown sections); `onShown` resets it and scrolls to the top. E2E `island-scroll-more` + `island-reshow-few`.
- **Island order is FROZEN while it is shown (owner 2026-10-01):** `frozenOrder` (island.js, id → rank) is taken on the first render after each show (`onShown` resets it); later snapshots keep that order, so a priority click never moves the row under the pointer; a renamed id (priority is part of the id) inherits its rank. The next appearance sorts fresh.
- **Island undo bar FLOATS** (`#undo-bar` `position: absolute` at the pill's bottom, owner 2026-09-28): showing or hiding it never grows or shrinks the island (it overlays the last row for its few seconds). E2E `island-undo-height`.
- **Island rows (owner, 2026-09-25):** row click = stage/unstage **Now** (the fast path). Edit = the pencil button at row end — it retracts the pill, opens the tasks window, and puts the editor on top for that task (`editFromIsland` in island.js). ## House rules (learned the hard way)

1. **Transparent island window:** NEVER add an OUTER CSS box-shadow to the pill — it clips against the window edge and shows as a square halo. Inset shadows are fine (the glass thickness uses them); E2E `island-glass` asserts `outerShadows=0`.
2. **Nested flex:** every flexible ancestor in a chain that holds long `nowrap`/clamped text needs `min-width: 0` — flex items default to `min-width: auto` and will stretch the window.
3. **`[hidden]`**: any element with a `display` rule needs the global `[hidden] { display: none !important; }` guard (already in both CSS files — keep it).
4. **Task IDs change** when title/priority/due change; `update-task` returns the new id and the side-panel editor adopts it (every autosave).
5. **Native controls:** `color-scheme: light dark` on `:root` keeps select/scrollbar icons visible in both themes; all colors go through CSS tokens. Never use `type=number` / `type=time` for user-facing values: they show the OS locale's digits (see "Numbers and times are plain text fields").
6. **Zoom is locked** (`lockZoom`) — do not remove; accidental Ctrl+scroll wrecks the layout.
7. New IPC: add to the handler in main.js AND the matching preload, same channel name, then run `node --check` on all touched js files.
8. No new npm dependencies without a strong reason. No personal data (paths, names, sample tasks) in code, tests, or docs.
9. **Electron 44 clipboard is async** — `await clipboard.writeText/readText`, or you'll stringify a Promise.
10. **Autostart:** `applyAutoStart()` must pass `app.getAppPath()` (dev) + `--hidden` in login-item args — a bare electron.exe Run entry boots the default Electron welcome page. `--hidden` launches also skip the 1.5 s launch pop; startup re-applies the registration as self-heal.
11. **State lives in `app.getPath('userData')/state.json`** (writable when packaged — asar is read-only). Never write next to `__dirname`.
12. **Island geometry:** top-anchored at `wa.y + 10`, grows DOWN via the `island-size` IPC (height + optional space borrowed above, clamped to the work area). Don't bottom-anchor it.
13. **Dismiss timer, one rule (`armDismiss` in island.js):** pinned or a broken note → no timer. Pointer anywhere on the island window (the one hover truth: documentElement enter/leave) or keyboard mode → the timer is held FULL (`holdFull`), whatever you click. Otherwise one full countdown, started once; re-renders never restart or pause it. Leave → a fresh full countdown. A click that hides the island under the pointer never gets its mouseleave, so `retract()` resets hover, and every show re-arms from scratch.
13a. **The island is focusable while shown** (`showIsland` → `setFocusable(true)` before `showInactive()`; `hideIsland` sets it back to false). A non-focusable (WS_EX_NOACTIVATE) window that was hidden and shown again DROPS every real mouse click on Windows: the island looked alive after a timed pop but ignored all clicks (owner report 2026-09-27; reproduced only with real OS clicks via SetCursorPos/mouse_event, CDP clicks never show it). `showInactive` still never takes focus (verified: the foreground window is unchanged after a timed pop); only the user's own click activates the island.
13b. **Shortcut reliability:** the island window runs with `backgroundThrottling: false`. A throttled hidden renderer froze the retract animation, so the window stayed "visible" and the next shortcut press only dismissed it (the owner saw "press twice"). `retract()` has a 320 ms hard backstop that never hides a pill that has been re-shown in the meantime.
14. **i18n at load:** every renderer calls `I18N.applyDoc(LANG)` once at startup. Placeholders, titles and aria labels have no inline fallback, so English windows used to show empty placeholders.
15. **Settings migration:** `migrateSettings()` upgrades old keys (`intervalMin` → `workIntervalMin`). When adding settings keys, give them a DEFAULT_SETTINGS entry so old state.json files merge cleanly.
